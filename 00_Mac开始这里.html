涂层图像测试：Mac 软件准备包 V0.1.1

已改为 macOS 启动流程。首次配置需要联网；图像转换在本机完成，不上传照片。
这是 Python 图形界面源码包，未打包为签名、公证的 .app，也未在 Mac 实机测试。

最短操作路线

只先练习 ImageJ： 安装 Mac 版 Fiji，直接运行包内 imagej 文件夹的两个宏。无需先安装 Python、ExifTool 或 RAW 转换器。

使用 RAW 转换器： 安装 Python → 完整解压本包 → 双击 01_install_mac.command → 成功后双击 02_start_mac.command。ExifTool 可另行安装，供完整元数据记录。

1. 先准备 Python

建议从 Python 官网安装普通 Python 3.13 的 macOS universal2 安装包。已有 Python 3.12 也可使用；本包不采用自由线程实验版本，不调用系统自带的 /usr/bin/python3。

官方安装包包含 Tkinter 所需的 Tk，适合这个桌面界面。不要只在现有 Python 中执行 pip install tkinter。

Python Mac 下载：
https://www.python.org/downloads/macos/

Python 官方 Mac 安装说明：
https://docs.python.org/3.13/using/mac.html

安装后，在“应用程序 → Python 3.13”中运行 Install Certificates.command。它是 Python 官方安装的一部分；联网依赖下载遇到证书错误时，先检查这一环节，不要关闭 HTTPS 证书校验。

本包的 Mac 安装入口针对 macOS 11 或更高版本。Apple 芯片需原生 arm64 Python；Intel 需 x86_64 Python。可在苹果菜单“关于本机”查看芯片。脚本会检测架构，无需手动选依赖文件。

使用 Homebrew 的现有环境也可被发现，但必须安装了对应版本的 Tk；缺少 Tk 时优先采用上述 python.org 安装方式，无需为这个工具额外安装 Homebrew。

2. 解压与安装

把整个 coating_imaging_mac_v011 文件夹放在可写位置，例如“文稿/CoatingTest”。先放到计划长期使用的位置，再建立环境。不要直接从 ZIP 中启动，也不要只拿出一个 command 文件。

双击 01_install_mac.command。它会：检查 Mac 版本和 Python；在工具文件夹下建立 .venv；安装固定依赖；运行合成数值测试；保存环境记录和日志。

本包只请求预编译的 Python 安装包，找不到匹配包时会停止，不自动转入源码编译或要求安装 Xcode。脚本不使用 sudo，不覆盖系统 Python，不自动安装 ExifTool 或 Fiji，不改系统安全设置。

Apple 芯片分支固定 rawpy 0.27.1；Intel 分支固定 rawpy 0.25.1。原包的 rawpy 0.27.1 未提供 Intel Mac 预编译包，因此 Intel 使用另一个明确固定的版本。底层 LibRaw、系统、架构全部进入记录。两种分支产生的实验指标未经交叉验证不得混排。

其余固定依赖：NumPy 2.3.5、tifffile 2026.5.15、Pillow 12.3.0。安装失败时保留 logs 中的日志，不要自行把所有版本改成 latest。

安装成功后，再双击 02_start_mac.command。它会打开本地桌面窗口，终端只显示启动日志，窗口成功出现后可以关闭终端。日常操作使用按钮和文件选择框，本版没有拖放导入。

3. 安装 ExifTool

从官方安装页下载 Mac 版 .pkg，按照系统安装流程安装：
https://exiftool.org/install.html

官方 .pkg 通常把可执行文件放在 /usr/local/bin/exiftool；Homebrew 安装通常在 /opt/homebrew/bin/exiftool（Apple 芯片）或 /usr/local/bin/exiftool（Intel）。本工具会自动查找这些路径。

安装后重新打开工具，或点击“自动查找”。需要手选时请选择 exiftool 可执行文件，不要选择 .pkg 安装包，不要选择 Windows 的 .exe。在系统文件对话框按 Command+Shift+G，可输入 /usr/local/bin 进入对应目录。

缺少 ExifTool 时仍可练习解码，但相机曝光等字段标为 incomplete/未核查，不能算元数据检查通过。软件仅读取规定的拍摄字段；缺失信息不猜测填充。

4. 转换第一张 RAW

在窗口中选择 RAW；确认 ExifTool 路径；从一张参考 RAW 建立固定配置；保存配置 JSON；选择输出目录；点击批量转换。

旧照片只用于测试文件能否解码，不能代替正式灯光的白平衡或曝光设置。第一版限定为 Bayer RGBG 布局，遇到不支持的数据布局会报错。

每张照片输出 Y_linear32.tif、可选的 RGB_linear16.tif、preview_DISPLAY_ONLY.png 和 metadata.json；整批输出配置、CSV 及 JSON 汇总。原 RAW 保持不变。

Y 是统一编码尺度下的亮度相关数据，未标定为真实亮度、L*、人眼可见度或污染物质量。PNG 仅用于查看。真实照片仍需检查对齐、曝光、反光状态和测试区域。

5. Fiji / ImageJ：Mac 应该下载哪一个

官方页面：
https://imagej.net/software/fiji/downloads

在 macOS 对应行选包含 Java 的包。Apple M 系列选 arm64，Intel 选 x86-64。当前官方“Latest Downloads”提供两种架构，要求 macOS 11 或更高。不要误选 Portable (no JDK)，除非已经自行配置匹配的 Java。

解压后将整个 Fiji.app 放在自己有写入权限的位置，例如用户目录下的 Applications，然后打开。不要只移动 app 内部某个可执行文件。初次准备完成后记录 Fiji 和 ImageJ 版本，正式比较期间不随意更新。

在 Fiji 菜单使用 Plugins → Macros → Run…：

1. 运行 imagej/02_check_known_numbers.ijm。预期 V=0.03125。
2. 运行 imagej/01_difference_fixed_roi.ijm。干净图选 demo/00_clean_Y.tif，变化图选 demo/02_local_change_Y.tif；ROI 取 x=0、y=0、width=256、height=256。预期 V=0.0078125。

演示全部是已知数值合成图，用于核对算术、输入和输出，不能作为材料效果证据。Python 测试与 Fiji 宏的实机运行需要分别核对。

正式计算只用按同一配置生成且已对齐的单通道 Y_linear32.tif。宏做绝对差分与固定区域均值，不计算面积、不自动配准、不拉伸像素、不设置合格等级。擦后测试区域应覆盖完整擦拭路径。

6. Mac 常见问题

系统提示无法验证开发者或来源： 本包的 command 为可读源码脚本。先确认文件来源并检查脚本；需要放行时使用苹果官方提供的针对单个项目的“系统设置 → 隐私与安全性 → 仍要打开”。不要关闭整个系统的 Gatekeeper，也不要运行网上的一键全盘移除隔离属性命令。公司管理的 Mac 应遵循 IT 政策。
https://support.apple.com/en-us/102445

提示没有执行权限： ZIP 已保存 command 的执行位，个别解压工具仍可能丢失。可在 Terminal 输入 /bin/bash 后加一个空格，再把 01_install_mac.command 从 Finder 拖入窗口，按回车运行；启动脚本也可按同样方式运行。此操作只指定解释器，不修改系统安全策略。

双击后没有窗口： 先查看 logs/gui_*.log，再运行 03_check_environment.command。若提示缺少 _tkinter，请使用 python.org 普通安装包；若提示未安装，先运行安装脚本。

已移动工具目录或换了架构： Python 虚拟环境不保证可迁移。用 Finder 的 Command+Shift+. 显示隐藏文件，仅删除本工具目录里的 .venv 和 .installation_ready，然后重新安装。不要删除原始照片、输出目录、系统 Python 或其他项目的环境。

装好但打不开 RAW： 保留错误信息、相机型号和 RAW 类型。库支持相机与具体编码方式的范围有限；不能通过更改文件后缀解决，也不能把旧版输出与新版输出混合。

参数一致但画面变了： 元数据检查只比对文件里写入的字段。它无法保证灯的位置、板面倾角、对焦及污染延迟一致，仍需现场记录与照片核查。
